Detailed Before vs. After Upgrades

1. Watchlist Pre-cache Engine with 90-Day LRU Management

services/watchlist_precache_service.py

Previously, whenever a user clicked a symbol in a watchlist, OpenAlgo made a live HTTP request to Angel One's server. When flipping through 400 stocks, Angel One's 3 req/sec limit caused massive queuing, leading to History request timed out.

❌ Before Implementation
  • On-Demand Broker Calls: Every symbol click hit broker servers live.
  • Severe Lag: 2-5 seconds delay per stock flip.
  • No Background Loading: Watchlist import did not download historical candles.
  • Disk / Memory Bloat Risk: No mechanism to prune old or obsolete stock data from previous days/weeks.
✅ After Implementation
  • Background Auto-Precache: Importing a watchlist automatically fires a background thread that ingests daily candles for all symbols at a safe 0.35s interval.
  • 48-Hour Freshness Check: If data is already downloaded within 48 hours, it skips redundant API calls instantly.
  • 90-Day LRU Pruning: Automatically maintains lru_cache_tracker. Symbols not accessed in 90 days are deleted from DuckDB, preventing storage explosion.

2. Dual-Lane Rate Limiter & Broker Timeout Elimination

services/history_service.py

While background pre-caching was downloading 281 stocks (taking ~2-3 minutes), user chart clicks were being placed at the very back of a 281-item queue, triggering BrokerBusyError: History request timed out.

❌ Before Implementation
  • Single FIFO Queue: Interactive chart clicks shared the exact same queue as background batch jobs.
  • Starvation: If 200 background items were downloading, a user clicking a stock had to wait 70+ seconds, blowing past the 10-second timeout.
  • Cache Miss on Interactive: Even if data was downloaded, interactive clicks still attempted broker re-validation.
✅ After Implementation
  • Priority Fast Lane: Interactive clicks (background=False) bypass the background queue and claim the immediate next available 0.35s slot.
  • Cache-First Resolution: get_history() checks DuckDB first. If local data exists, it returns in <15ms without touching the broker network.
  • Auto-Cache on Miss: If a stock was not precached, downloading it once immediately saves it to DuckDB and touches the LRU tracker.

3. Windows DuckDB Concurrency & RLock Mutex Protection

database/historify_db.py

DuckDB on Windows requires exclusive file locks. When the background thread was writing candles while the Flask web server thread read candles, Windows raised: IOException: Cannot open file ... used by another process.

❌ Before Implementation
  • Thread Collision: Flask threads and precache threads opened historify.duckdb simultaneously.
  • Crash on Windows: Hard OS lock errors caused failed chart loads and aborted downloads.
  • Deadlocks in LRU: evict_lru_older_than() called delete_market_data() while still holding the connection context.
✅ After Implementation
  • Process-Wide RLock: _historify_db_lock = threading.RLock() guards every get_connection() call.
  • Exponential Backoff: Retries up to 5 times (increased from 3) with jittered sleep, guaranteeing graceful access on busy threads.
  • Decoupled Eviction: Expired symbols are queried and closed before executing deletions, eliminating nested lock deadlocks.

4. NSE Suffix Matching, BSE Scrip Resolution & 500 Watchlist Cap

database/token_db_enhanced.py & database/watchlist_db.py

Screener exports contained BSE scrip codes (e.g. 544809), NSE SME series (e.g. GENXAI-SM, BLUEWATER-ST), and the default watchlist limit was strictly capped at 250 items.

❌ Before Implementation
  • Hardcoded 250 Cap: MAX_ITEMS_PER_LIST = 250 threw 409 Conflict when importing the 281-stock scanner.
  • BSE Scrip Failure: Numeric scrip codes failed lookup in symbol database.
  • SME Suffix Mismatch: Symbols like GENXAI failed if the exchange token was registered as GENXAI-SM.
  • Unwanted -EQ Appending: Precache incorrectly transformed standard stocks into HINDZINC-EQ.
✅ After Implementation
  • 500 Item Capacity: Increased MAX_ITEMS_PER_LIST = 500, effortlessly supporting 281 and 500 stock scans.
  • Smart Series Resolution: Added automatic fallback across series suffixes (-SM, -ST, -EQ, -RR, -IV).
  • BSE Scrip-to-Ticker Translation: Numeric scrips automatically resolve to trading symbols.
  • Exact Symbol Preservation: Cleaned precache pipeline to preserve canonical OpenAlgo symbols.

5. TradingView-Style Keyboard Rapid Navigation & Auto-Scroll

frontend/src/pages/Trading.tsx & WatchlistPanel.tsx

Manually clicking stock rows with the mouse across 500 stocks causes fatigue and delays chart analysis. Traders need native TradingView keyboard cycling (Space / ArrowDown) with automatic watchlist scroll tracking.

❌ Before Implementation
  • Mouse Click Only: Users had to manually aim and click each stock in the sidebar.
  • Space Bar Interference: Pressing space triggered browser page scroll or button focus toggles.
  • No Viewport Sync: Sidebar watchlist did not scroll to follow the active stock.
  • No Cross-Component Sync: Trading.tsx had no live reference to the loaded watchlist items.
✅ After Implementation
  • Global Capture Key Listener: Space, Shift+Space, and Arrow keys cycle next/previous stocks instantly on the focused chart pane.
  • Input Guard: When typing in search bars, order dialogs, or dropdowns, keyboard cycling is cleanly suspended.
  • Auto-Scroll Follow: The active stock row smoothly scrolls into view in the sidebar using scrollIntoView({ block: 'nearest' }).
  • Pre-compressed Vite Build: Rebuilt and pre-compressed with Gzip/Brotli for instant web load.
